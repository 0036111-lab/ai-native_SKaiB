# Автономный исполнитель Аутрич SKaiB

Машиночитаемый профиль запуска: [autonomous-worker.yaml](./autonomous-worker.yaml).

## Назначение

Hermes выполняет безопасные фоновые этапы процесса. Он работает как сервисный субъект `service:hermes-outreach`, получает только необходимые GatewayMCP scope и не имеет прямого доступа к токенам CRM, Object Storage, почты или LLM-провайдера.

Для каждого задания Hermes обязан использовать workspace `CRM` с `workspace_id=6e16976a-03f0-5f88-8791-6362ab80a424`. Значение фиксируется оркестратором и не выбирается моделью. Задание с другим или отсутствующим `workspace_id` переводится в `waiting_for_human`; автоматически создавать новый workspace запрещено.

## Обязательный контекст Model Router

Каждый текстовый LLM-вызов направляется через GatewayMCP `/privacy/v1` с заголовками:

```text
X-Gateway-Workflow: skaib-outreach
X-Gateway-Stage: <stage>
X-Gateway-Execution-Mode: autonomous
```

Интерактивный запуск человеком использует `X-Gateway-Execution-Mode: interactive`. Исполнитель не подменяет этап и не передаёт модель напрямую в обход решения GatewayMCP.

## Карта этапов

| Этап | Режим | Автономность | Результат |
|---|---|---:|---|
| `completeness_check` | cheap-fast | Да | Список заполненных полей и пробелов |
| `data_normalization` | cheap-fast | Да | Нормализованные предложения без выдумывания фактов |
| `internal_search` | без LLM | Да | Кандидаты из источника истины |
| `external_research` | balanced | Нет | Запрос на отдельное разрешение человека |
| `company_space_match` | strong-reasoning | Да | Объяснимый MATCH с источниками и пробелами |
| `candidate_ranking` | balanced | Да | Рейтинг без автоматического исключения |
| `contact_verification` | без LLM | Да | Статус проверки официального контакта |
| `draft_email` | strong-writing | Нет | Черновик только после одобрения обращения |
| `draft_fact_check` | balanced | Да | Независимая проверка фактов черновика |
| `reply_classification` | cheap-fast | Да | Тип ответа и предлагаемая задача |
| `send_email` | без LLM | Нет | Только подтверждённый корпоративный маршрут |

Конкретные модели назначаются администратором в GatewayMCP, а не в skill.

## Машина состояний задания

```text
pending -> claimed -> running -> completed
                    -> waiting_for_human
                    -> retry -> running
                    -> failed
```

- `claimed` содержит владельца lease и срок действия.
- Повтор разрешён только для идемпотентных операций.
- `waiting_for_human` не возвращается в автономное выполнение без подтверждённого решения.
- После истечения lease задачу может забрать другой worker, используя тот же idempotency key.

## Разрешённые автономные действия

- читать подтверждённые `PROPERTY`, `SPACE`, `COMPANY`, `MATCH`, `COMMUNICATION` и задачи в разрешённом workspace;
- проверять полноту и формировать задачи проверки;
- искать во внутренней базе;
- создавать объяснимые предложения MATCH;
- ранжировать кандидатов без удаления и исключения;
- классифицировать новые ответы;
- создавать задачу `Ответить` или задачу повторного касания;
- сохранять безопасную телеметрию этапа, профиля модели, длительности и статуса.

## Запрещённые автономные действия

- проводить внешний поиск без отдельной команды человека;
- использовать непроверенный контакт;
- исключать кандидата;
- одобрять обращение от имени человека;
- отправлять письмо или фиксировать статус `отправлено`;
- удалять данные, менять права или выдавать новые scope;
- читать прямые токены внешних систем;
- обходить GatewayMCP или менять назначенный Model Router профиль.

## Ограничители запуска

Для каждого задания оркестратор задаёт:

- `max_steps`;
- `deadline_at`;
- `max_retries`;
- `idempotency_key`;
- разрешённые stage;
- workspace и resource grants;
- дневной и заданийный бюджет;
- маршрут уведомления человеку.

При неизвестном этапе, отсутствии источника, превышении бюджета или конфликте данных исполнитель завершает работу в `waiting_for_human` либо `failed`, не подставляя предположения.
