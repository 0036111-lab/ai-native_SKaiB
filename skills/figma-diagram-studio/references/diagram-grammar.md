# Diagram grammars

Choose one primary grammar based on the question the diagram answers.

## C4 / system architecture

Use nested system boundaries and three visual roles: people, internal systems, external systems. Show protocols or interaction types on connectors. Create separate C1/C2/C3 views instead of forcing all levels onto one canvas.

## Process / service flow

Use a single dominant direction. Keep steps short and verb-led. Decisions get distinct diamond treatment; human approvals and system automation must be visually different. Exceptions branch away from the main path and rejoin clearly.

## Ecosystem / market map

Use proximity and containment for categories, not decorative arrows. Size or emphasis must encode a named measure. If no reliable measure exists, keep node sizes equal and say so.

## Operating model / ownership

Use horizontal stages and vertical owners, or vice versa. Show handoffs, decision rights, inputs, and outputs. Avoid a matrix if the actual story is sequential.

## Roadmap / capability map

Separate time from maturity. Use lanes for workstreams and a limited milestone vocabulary. Dependencies should be exceptional and explicit, not a web across every item.

## Visual system defaults

- Canvas: warm white or very light neutral.
- Text: near-black; secondary text muted but accessible.
- Accent: one project color.
- Status: green = verified/current, amber = proposed/check, red = blocked/risk, gray = external/context.
- Typography: one family, three levels maximum.
- Shapes: one main card shape, one decision shape, one callout style.
- Connectors: one default weight; heavier only for the principal path.
